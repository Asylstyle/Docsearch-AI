# DocSearch AI

RAG-сервис для вопросов по текстовым PDF. Он сохраняет исходные номера страниц,
находит фрагменты и передаёт их в LLM для ответа с цитатами [n].
Загрузка и поиск работают локально на CPU без ключа. **Реальная генерация не
проверена**: при найденном контексте без ключа /ask возвращает 503.

## Восстановленная история

По словам автора, исходная история прежней работы над проектом была потеряна.
По его запросу даты 53 существующих коммитов приблизительно восстановлены:
равномерно распределены между 1 июня и 9 сентября 2026 года с сохранением
порядка, содержимого и авторства Asylstyle. Эти даты являются реконструкцией,
а не подтверждённой хронологией разработки или датами проведённых проверок.
Результаты, временные отметки экспериментов и журналы оставлены без изменений.
Это раскрытие добавлено отдельным коммитом с фактической текущей датой.

## Устройство

~~~text
PDF → pypdf → страницы → чанки внутри страницы → E5 → PostgreSQL / pgvector
вопрос → E5 [+ TF-IDF / RRF / CrossEncoder] → top-k → LLM → ответ [n], документ, страница
~~~

| Компонент | Стек |
|---|---|
| API / настройки | Python 3.11, FastAPI, pydantic-settings |
| База | PostgreSQL 16, pgvector, синхронный SQLAlchemy 2, psycopg 3, Alembic |
| PDF | pypdf, без OCR |
| Эмбеддинги | Sentence Transformers, intfloat/multilingual-e5-small, 384, CPU |
| Baseline / гибрид | scikit-learn TF-IDF word 1–2, char_wb 3–5; RRF |
| Reranker | cross-encoder/mmarco-mMiniLMv2-L12-H384-v1, CPU |
| Генерация | OpenAI SDK, Chat Completions, temperature=0 |
| Запуск / проверки | Docker Compose, pytest |

Три таблицы: Document, Chunk, QueryLog. ID документа — первичный ключ БД;
удаление каскадно удаляет чанки. Пустые страницы пропускаются, исходные номера
с 1 не сдвигаются; pages_count включает все страницы. Чанк — до 800 символов,
перекрытие 100, chunk_index сквозной с 0. E5 использует query: / passage:
и нормализованные эмбеддинги.

По dev выбран **e5**. Режимы: e5, hybrid_rrf, e5_rerank, hybrid_rerank.
RRF суммирует 1/(60+rank), ранги с 1, ключ chunk_id; объединяет top-20 E5
и tfidf_char. До hybrid_rerank объединение обрезается до 20.
CrossEncoder получает сырые пары (query, chunk_text).
Модели кешируются, результаты запросов — нет. TF-IDF индекс строится лениво
и сбрасывается после успешной загрузки/удаления; индекс рассчитан на один процесс.
Score E5 = 1 − cosine distance; RRF score и reranker logits имеют другой смысл.

Фрагменты в промпте — недоверенные данные. Sources строятся сервером только по
валидным [n], без дублей (document_id, page). Неверные номера игнорируются;
ответ без валидных ссылок имеет sources=[] — это не доказательство поддержки
утверждений. При пустом поиске LLM не вызывается.

## Запуск

Нужны Docker Desktop с работающим Linux engine и свободный localhost:8000.
Из корня репозитория:

~~~sh
docker compose up --build -d
curl http://localhost:8000/health
~~~

Ответ: {"status":"ok"}. Swagger: [localhost:8000/docs](http://localhost:8000/docs).
В Windows при необходимости используйте curl.exe.
Compose ждёт БД, выполняет alembic upgrade head и запускает uvicorn.
Тома postgres_data и model_cache сохраняются. Первый поиск скачивает E5 при
отсутствии кеша и медленнее прогретого. torch==2.9.0+cpu исключает CUDA-зависимости.

.env необязателен для демо-поиска. Для своих настроек скопируйте .env.example
в .env (игнорируется Git). Пароль БД в Compose — только локальный демо-default.

| Переменная | По умолчанию / назначение |
|---|---|
| DATABASE_URL | PostgreSQL через psycopg, сервис db |
| EMBEDDING_MODEL / EMBEDDING_DIM | intfloat/multilingual-e5-small / 384 |
| CHUNK_SIZE / CHUNK_OVERLAP | 800 / 100 |
| SEARCH_MODE | e5; ещё hybrid_rrf, e5_rerank, hybrid_rerank |
| RERANK_MODEL / RERANK_CANDIDATES | указанный CrossEncoder / 20 |
| LLM_API_KEY | пусто; не коммитить и не отправлять в чат |
| LLM_BASE_URL | https://api.openai.com/v1 |
| LLM_MODEL | существующий default gpt-5.6-terra; доступность API не проверена |

Для LLM нужна отдельная безопасная настройка и разрешение на оплачиваемые
запросы. Ключи в этой работе не настраивались, провайдер не вызывался.
Имя модели в конфигурации не подтверждает доступ к ней.

## Корпус

[data/corpus.csv](data/corpus.csv): 14 исходных ссылок официальных сайтов МГУ/ВМК,
РГГУ, СамГТУ, ВШЭ, Назарбаев Университета, ТГУ имени Державина и
Карагандинского университета Казпотребсоюза.
Скачано и загружено **10 PDF, 175 страниц, 171 с текстом, 644 чанка**.
Это исторический демо-снимок, **не актуальные правила и не юридическая справка**.
Редакции МГУ 2026 и ВМК 2022 имеют разную область действия.

Две команды из корня используют Python/pypdf внутри образа:

~~~sh
docker compose run --rm -v "${PWD}/data:/app/data" api python scripts/download_corpus.py
docker compose run --rm -v "${PWD}/data:/app/data" api python scripts/ingest_corpus.py --api-url http://api:8000
~~~

В PowerShell ${PWD} также обозначает текущий каталог. Это инструкции
воспроизведения; первоначальный запуск скриптов описан в журнале.
Download пропускает валидные PDF, проверяет байты, скачивает атомарно с лимитами
и продолжает после ошибки. Ingest сначала читает /documents и пропускает точное
имя со статусом ready; при ошибке списка загрузки не начинаются.

При сборе hse-assessment-2021 и hse-parttime-assessment-2020 вернули не PDF;
keu-dormitory-2024 — HTTP 500, nu-ethics-ru — DNS error.
Ссылки сохранены, редакции не подменялись. Удалённые файлы могут измениться
или исчезнуть; байтовая воспроизводимость не обещается.
PDF и полный извлечённый текст не публикуются в Git; права остаются у источников,
единая лицензия всего корпуса не подтверждена.

## API

Команды и контракты ниже не являются выдуманными результатами LLM.
ID и время зависят от БД. Для DELETE замените 123 на ID своего демо-документа.

~~~sh
# 1. 200, {"status":"ok"}
curl http://localhost:8000/health

# 2. 201, Document с id, status, pages_count
curl -F "file=@data/pdfs/hse-dormitory-2017.pdf" http://localhost:8000/documents

# 3. 200, массив Document
curl http://localhost:8000/documents

# 4. 200, массив SearchHit
curl -G http://localhost:8000/search --data-urlencode "q=В какие часы в общежитии ВШЭ нужно соблюдать тишину?" --data-urlencode "k=5"

# 5. При найденных фрагментах без ключа — 503
curl -X POST http://localhost:8000/ask -H "Content-Type: application/json" -d '{"question":"В какие часы в общежитии ВШЭ нужно соблюдать тишину?","k":5}'

# 6. 200, массив HistoryItem, новые первыми
curl "http://localhost:8000/history?limit=20"

# 7. 204 без тела; 404 для отсутствующего документа
curl -X DELETE http://localhost:8000/documents/123
~~~

Ручной поиск тишины вернул hse-dormitory-2017.pdf, page=7.
SearchHit также содержит chunk_id, document_id, text, score.
Успешные /search и /ask пишут QueryLog; /history содержит query_type, question,
answer, sources, created_at. При пустом поиске /ask возвращает 200:

~~~json
{"answer":"В документах нет ответа на этот вопрос.","sources":[]}
~~~

Пустой поиск проверен офлайн с заглушкой. Если похожие фрагменты найдены,
но ответа в них нет, отказ должна сформировать LLM — живой моделью это
не проверено. При найденном контексте с принудительно пустым ключом проверен 503.
SourceRef содержит document_id, filename, page; метаданные берутся из поиска.

Лимит загрузки 10 MiB. Неверные, зашифрованные и PDF без текста отклоняются;
при ошибке ingestion сохраняется failed без частичных чанков.
Имя очищается до basename; оригинальные PDF сервер на диск не сохраняет.

## Оценка и разметка

[eval/questions.jsonl](eval/questions.jsonl): 50 вопросов — 40 answerable,
10 unanswerable, в том числе 10 cross_university с названным вузом.
Seed=42, стратификация по type: dev30/test20, answerable24/16.

Происхождение: **черновик LLM + автоматическая проверка (дословный поиск цитат
через pypdf, второй проход на полноту gold и отсутствие ответов); вручную человеком
не размечалась**. [Аудит](eval/label_audit.md) перечисляет изменения до фиксации SHA.
Поиск отсутствия ответа не является формальным доказательством.
Dev/test используют общие документы: это held-out вопросы, не вузы.

Контрольная сумма замороженного test: `a89172651d233cb9ddde66c68939cc51377ab20a40066b337644917c3773b0f2`

SHA256 UTF-8 json.dumps(test rows в порядке файла, ensure_ascii=False,
sort_keys=True, separators=(',', ':')). После аудита метки и split не менялись.
scripts/review_questions.py создаёт локальный eval/review.md для ручной проверки
при доступных data/pdfs; файл игнорируется Git.

Все методы получают те же 644 чанка ready-документов в read-only repeatable-read
снимке БД. E5 в eval всегда чистый E5 независимо от SEARCH_MODE.
Hit — filename+исходная страница, Doc-Hit — только файл; MRR — первый верный ранг.
Чанки не схлопываются до страниц.
Три запроса вне выборки прогревают каждый метод. Затем три свежих вызова на
вопрос/метод, медиана; порядок методов перемешивается с seed=42.
p50/p95 — распределение этих медиан. Загрузка модели/построение индекса исключены,
encoding, SQL, TF-IDF, rerank входят в полный вызов.

[Выбор](eval/results/method_choice.md) сделан только по dev: p50 <=1500 мс,
максимум Hit@1, затем самый простой метод в пределах двух правильных вопросов.
Выбран **E5: 13/24 top-1, p50 29.895 мс**. По test метод не перевыбирался.

## Выводы

- E5 нашёл правильный документ в top-5 для 15/16, страницу — для 10/16:
  ошибка часто в выборе страницы внутри документа.
- Символьный TF-IDF: Hit@5 10/16 против 6/16 у word; полезный CPU baseline.
- RRF дал Hit@5 12/16 при p50 41.9 мс; hybrid_rerank — 13/16 при 1242.8 мс.
  Эти test-наблюдения не использовались для смены выбранного E5.
- У E5 gold был среди top-20 в 16/16, после rerank в top-5 — 12/16.
  Hybrid-кандидаты покрывают 15/16; перестановка не восстанавливает отсутствующий чанк.
- Один retrieval-вопрос test = 6.25 п.п. (n=16); один вопрос всего test = 5 п.п.
  (n=20). Статистическая значимость не проверялась. Качество генерации и
  надёжность отказов из retrieval-метрик не следуют.

## Ограничения

Нет OCR, дедупликации по содержимому, фоновых очередей и восстановления
зависшего processing после аварии. Ingest пропускает готовое точное имя,
но другой filename может создать дубликат.
Один пользователь/localhost: нет авторизации и распределённого индекса.
Нет UI/сервера оригинальных PDF; документ и страница возвращаются в JSON.
Малая историческая выборка, нет человеческой проверки, документы общие для split.
Промпт не гарантирует защиту от всех инъекций. Семантическая поддержка ответа
и same-model judge живой моделью не проверены.
Версия модели не хранится у каждого вектора; зависимости не полностью
зафиксированы lock-файлом. Задержки — прогретый проход на общем CPU-компьютере.
