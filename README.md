# PDF RAG — загрузка и поиск

FastAPI, синхронный SQLAlchemy 2.0, PostgreSQL 16 + pgvector, Alembic.
Реализованы ingestion, список/удаление документов и семантический поиск с записью
QueryLog. Модели, схемы и сигнатуры каркаса сохранены. `POST /ask`, `GET /history`
и RAG пока заглушки HTTP 501. Тестов и UI нет.

## Запуск

```sh
docker compose up --build
curl http://localhost:8000/health
# {"status":"ok"}
```

OpenAPI: http://localhost:8000/docs. API доступен только на `127.0.0.1:8000`;
порт базы наружу не опубликован. `.env.example` необязателен: Compose содержит
демонстрационные значения. API-ключ не требуется. Пароль базы предназначен
только для локальной демонстрации. `.env`, PDF и локальные базы исключены из Git.

При старте API выполняются `alembic upgrade head` и `uvicorn`. Одна миграция
включает `vector` и создаёт `documents`, `chunks`, `query_logs`. Данные PostgreSQL
сохраняются в именованном томе. Остановка без удаления данных: `docker compose down`.

При первой загрузке/поиске скачивается `intfloat/multilingual-e5-small` из
[Hugging Face](https://huggingface.co/intfloat/multilingual-e5-small) (MIT в model card). Модель загружается лениво один раз на процесс,
работает на CPU; кеш весов сохраняется в отдельном томе Compose.
PyTorch закреплён как `torch==2.9.0+cpu` с CPU-index: суффикс `+cpu`, а не только
`--extra-index-url`, исключает автоматический выбор CUDA-сборки.

## API

| Маршрут | Контракт |
| --- | --- |
| `GET /health` | `{"status":"ok"}`, проверка процесса API |
| `POST /documents` | multipart `file`: текстовый PDF до 10 MiB → Document, HTTP 201 |
| `GET /documents` | список документов и статусов |
| `DELETE /documents/{id}` | числовой ID, HTTP 204; чанки удаляются каскадно |
| `GET /search?q=...&k=5` | `list[SearchHit]`, k 1–100; запись QueryLog |
| `POST /ask` | `{"question":"...","k":5}` → AnswerResult, заглушка 501 |
| `GET /history?limit=20` | заглушка 501 |

```sh
curl -F 'file=@public-document.pdf' http://localhost:8000/documents
curl 'http://localhost:8000/search?q=release%20deadline&k=5'
curl http://localhost:8000/documents
```

## Обработка

`extract_pages` пропускает пустой текст, сохраняя исходные номера страниц с 1.
`pages_count` считает все исходные страницы, включая пустые в конце. Чанки
разбиваются по символам без пересечения страниц, с перекрытием и сквозным
`chunk_index`. Требуется `CHUNK_SIZE > 0` и `0 <= CHUNK_OVERLAP < CHUNK_SIZE`.
Документ сначала фиксируется как `processing`, затем атомарно сохраняются чанки
и статус `ready`. При ошибке частичные чанки откатываются, статус `failed`
фиксируется отдельной транзакцией. Пустые/сканированные и зашифрованные PDF
не поддерживаются. Повторная загрузка создаёт отдельную запись, дедупликации нет.

Эмбеддинги: `passage: ` для чанков и `query: ` для запросов,
`normalize_embeddings=True`, 384 измерения. Поиск использует cosine distance
pgvector, `score = 1 - distance`, join с Document и фильтр `status=ready`.
Сходство не является вероятностью правильного ответа. Текст PDF не исполняется
как инструкции. Полный файл не сохраняется; имя используется только как метаданные.
История хранит запрос и источники. Используйте публичные документы в этой
однопользовательской localhost-демонстрации. Ограничение чтения 10 MiB не заменяет
лимит multipart-запроса перед парсингом, изоляцию парсера и защиту от PDF-бомб.
E5 обрезает длинные входы по токенам модели; символьное разбиение не гарантирует
попадание каждого языка в токеновый лимит.

Настройки: `DATABASE_URL`, `EMBEDDING_MODEL`, `EMBEDDING_DIM=384`, `LLM_API_KEY`,
`LLM_MODEL`, `CHUNK_SIZE=800`, `CHUNK_OVERLAP=100`. Колонка — `Vector(384)`.
При смене модели нужен переиндексированный корпус: версия модели в схеме не хранится.

## Без Docker: Windows / PowerShell

Для текущих ML-зависимостей используйте Python 3.11. Ранее созданное локальное
окружение Python 3.14 проверяло только старую версию без ML.

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
$env:DATABASE_URL='postgresql+psycopg://YOUR_USER:YOUR_PASSWORD@localhost:5432/YOUR_DATABASE'
.\.venv\Scripts\alembic upgrade head
.\.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Нужны существующая база, доступ и установленный pgvector. Спецсимволы пароля
должны быть URL-кодированы. Хост `db` из `.env.example` предназначен для Compose.
Прямой запуск Uvicorn не запускает миграцию. `/health` не подключается к базе.
Остановка сервера — Ctrl+C.

## Проверка

Исходный каркас проверен в Docker: Python 3.11.17, PostgreSQL 16.15,
pgvector 0.8.7, Alembic 0001, три таблицы и колонка `vector(384)`.
`/health` вернул HTTP 200 и `{"status":"ok"}`.
Новая сборка `docker compose up --build -d` и ручной HTTP-проход выполнены:

- В контейнере `torch 2.9.0+cpu`, `torch.version.cuda=None`, CUDA недоступна,
  пакеты `nvidia-*` отсутствуют. Sentence Transformers 5.7.0 загрузил реальную E5.
- Синтетический PDF с пустыми страницами 1 и 4: POST → 201, `ready`,
  `pages_count=4`. Чанки `(index,page,length)`:
  `(0,2,800)`, `(1,2,800)`, `(2,2,759)`, `(3,3,69)`;
  перекрытия соседних чанков страницы 2 совпали на 100 символов.
- GET /search → 200: первым найден фрагмент про комнату калибровки 742
  с исходной страницы 3, score ≈0.90336. В базе вектор имеет 384 измерения,
  норму ≈1.00000001; QueryLog содержит `search`, вопрос и источники с page.
- Пустой PDF → 422, запись `failed`, `pages_count=2`, чанков 0.
- `k=0` → 422, POST /ask → 501. Удаление созданного демо → 204;
  связанных чанков после удаления 0. Удалены только два документа этого прохода;
  до и после проверки документов в базе было 0. Том PostgreSQL не пересоздавался.

Это ручная функциональная проверка на явно синтетическом PDF, не бенчмарк качества.
Ошибки БД во время commit, конкурентные запросы и аварийное завершение процесса
не имитировались. При аварийном завершении возможен оставшийся `processing`;
автоматического восстановления или повторной индексации в этой версии нет.
Unit/integration-тесты не написаны и не запускались согласно запросу.
Предыдущая полная реализация сохранена в соседней локальной резервной папке вне Git
и не восстанавливалась. Системные настройки и сторонние службы не менялись.
