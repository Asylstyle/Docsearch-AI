# PDF RAG — загрузка и поиск

## Корпус

`data/corpus.csv` содержит 14 ссылок на официальные сайты МГУ/ВМК МГУ, РГГУ,
СамГТУ, ВШЭ/ФКН ВШЭ, Назарбаев Университета, Карагандинского университета
Казпотребсоюза и ТГУ им. Державина. Темы: академический отпуск, аттестация,
оценки, общежитие, стипендии, поведение и этика. Это исторический демо-снимок
перечня источников, **не актуальные правила** и не юридическая консультация.
Русская редакция НУ 2020 года взята из официальной карточки
[123456789/422](https://regulations.nu.edu.kz/handle/123456789/422), где она
отмечена как архивная (Retired). Новая действующая редакция её не подменяет.

В окружении с зависимостями проекта и запущенным API:

```sh
python scripts/download_corpus.py
python scripts/ingest_corpus.py --api-url http://localhost:8000
```

Первый скрипт скачивает в `data/pdfs/`, проверяет сигнатуру, конец PDF и структуру
через pypdf, выводит число страниц и страниц с извлекаемым текстом. Уже корректные
PDF пропускаются; повреждённый файл заменяется только после успешной атомарной
загрузки. Лимит 10 MiB, сетевой timeout 30 секунд и бюджет скачивания 120 секунд.
Unicode и существующие `%HH` в URL не кодируются повторно. Небезопасные имена,
HTML-страницы вместо PDF, ошибки TLS, доступа и ссылки с ошибками не обходятся:
скрипт сообщает ошибку и продолжает. Итоговый код 1 означает частичный неуспех,
а не потерю уже скачанных файлов. OCR не добавляется; документы без текстового
слоя могут скачаться, но не будут пригодны для текущего ingestion.

Второй скрипт отправляет каждый локальный PDF в `POST /documents`, выводит
`filename,status,pages_count` и ID записи. Базовый адрес по умолчанию —
`http://localhost:8000`; `--api-url` его заменяет. Timeout загрузки в API —
300 секунд. Ошибка одного файла не останавливает остальные. Перед загрузкой
скрипт успешно получает GET /documents и пропускает точные имена, для которых
есть запись ready; при ошибке списка загрузки вообще не начинаются. Успешно
загруженные имена добавляются в набор пропуска. Это дедупликация только по имени,
не по содержимому: изменённый PDF с тем же именем тоже пропустится, а переименованный
может загрузиться повторно; параллельные запуски не защищены от гонки.
Скрипт не удаляет имеющиеся документы и не вызывает `/ask` или OpenAI.

Ссылки сохранены в исходных редакциях, даже если недоступны. Удалённые файлы
могут меняться или исчезать; без хешей это не побайтово воспроизводимый архив.
Публичная доступность не означает открытую лицензию: репозиторий НУ указывает
защиту авторским правом. PDF и полные извлечённые тексты не публикуются в Git;
в нём остаются только CSV, скрипты и описание. `data/pdfs/` исключён из Git.

## Оценка поиска

После сборки текущего образа:

```sh
docker compose exec api python -m scripts.eval_retrieval --split dev
```

По умолчанию k=5. Для reranker доступно 20 кандидатов, поэтому k от 1 до 20: при другом k имена
Hit@k, MRR@k и Doc-Hit@k меняются соответственно, а не называются ошибочно @5.
Оцениваются только answerable выбранной части; unanswerable не входят ни в
знаменатель, ни в задержку и не дают метрик отказа. Никаких вызовов `/ask` или LLM.

Методы используют один read-only REPEATABLE READ снимок: все чанки документов
со статусом ready. TF-IDF word: lowercase, ngram=(1,2); TF-IDF char:
analyzer=char_wb, ngram=(3,5). Оба считают cosine similarity. E5 вызывает
app.search.service.search_chunks напрямую в той же сессии. Чанки не объединяются
по страницам, дубликаты документов не удаляются; дубли имён отражаются в отчёте.
При равных оценках порядок определяется chunk_id. Нет QueryLog-записей через API;
число записей проверяется отдельными сессиями до и после выполнения.

Hit@1 — правильная пара filename/page на первом месте. Hit@5 — такая пара
где-либо в top-5, MRR@5 — обратный ранг первого правильного чанка или 0.
Doc-Hit@5 требует только правильный файл. Пропавшие gold-файлы/страницы
выводятся явно и останавливают оценку, вопросы не отбрасываются молча.

Задержка — wall time одного вызова retrieval. Для TF-IDF включены transform
запроса, cosine similarity, ранжирование и создание результатов. Для E5 —
кодирование запроса, SQL cosine search и создание результатов. Построение
TF-IDF-индекса и один общий прогрев на метод исключены и измеряются отдельно;
прогрев E5 включает инициализацию модели. Импорты и построение отчёта не входят.
Среднее по одному запуску на этом общем компьютере не является универсальным
бенчмарком оборудования или доказательством преимущества метода.

Результаты сохраняются в `eval/results/retrieval_dev.md` и `.json` внутри
контейнера; JSON включает число вопросов/чанков/документов, знаменатели по type,
настройки, версии пакетов, хеши корпуса/вопросов, ранги и метаданные хитов без
полных текстов PDF. Для копирования результата в рабочую папку после запуска:

```sh
docker compose cp api:/app/eval/results/. eval/results/
```

В начале проверяется test SHA-256 по ранее опубликованному определению README;
при несовпадении печатается WARNING, исходный хеш не исправляется. Во время dev
test-записи читаются только для этой проверки целостности и не передаются в поиск.
Test не запускать до отдельного решения; по результатам dev pipeline не настраивается.

Исходный прогон без reranker (коммит 462a624), dev/k=5: 24 answerable (simple=9, paraphrase=9,
cross_university=6), 6 unanswerable исключены. Все методы использовали
644 чанка 10 ready-документов. Missing gold=[]; дубликатов ready-имён нет.
QueryLog до/после: 2/2. Test SHA совпал с ранее сохранённым; **test не запускался**.

Это baseline по предварительным меткам ассистента, не проверенная человеком

QueryLog. Реализованы RAG `POST /ask` через OpenAI и `GET /history`.
Существующие модели, схемы и сигнатуры сохранены; добавлена схема HistoryItem.
Тестов и UI нет.

## Запуск

```sh
docker compose up --build
curl http://localhost:8000/health
# {"status":"ok"}
```

OpenAPI: http://localhost:8000/docs. API доступен только на `127.0.0.1:8000`;
порт базы наружу не опубликован. `.env.example` необязателен: Compose содержит
демонстрационные значения. Для загрузки/поиска и отказа без контекста API-ключ
не требуется; генерация `/ask` требует LLM_API_KEY. Пароль базы предназначен
только для локальной демонстрации. `.env`, PDF и локальные базы исключены из Git.

При старте API выполняются `alembic upgrade head` и `uvicorn`. Одна миграция
включает `vector` и создаёт `documents`, `chunks`, `query_logs`. Данные PostgreSQL
сохраняются в именованном томе. Остановка без удаления данных: `docker compose down`.

При первой загрузке/поиске скачивается `intfloat/multilingual-e5-small` из
[Hugging Face](https://huggingface.co/intfloat/multilingual-e5-small) (MIT в model card). Модель загружается лениво один раз на процесс,
работает на CPU; кеш весов сохраняется в отдельном томе Compose.
PyTorch закреплён как `torch==2.9.0+cpu` с CPU-index: суффикс `+cpu`, а не только
`--extra-index-url`, исключает автоматический выбор CUDA-сборки.

## API

| Маршрут | Контракт |
| --- | --- |
| `GET /health` | `{"status":"ok"}`, проверка процесса API |
| `POST /documents` | multipart `file`: текстовый PDF до 10 MiB → Document, HTTP 201 |
| `GET /documents` | список документов и статусов |
| `DELETE /documents/{id}` | числовой ID, HTTP 204; чанки удаляются каскадно |
| `GET /search?q=...&k=5` | `list[SearchHit]`, k 1–100; запись QueryLog |
| `POST /ask` | `{"question":"...","k":5}` → AnswerResult; k 1–20; QueryLog |
| `GET /history?limit=20` | list[HistoryItem], limit 1–100, created_at desc |

```sh
curl -F 'file=@public-document.pdf' http://localhost:8000/documents
curl 'http://localhost:8000/search?q=release%20deadline&k=5'
curl http://localhost:8000/documents
```

## Обработка

`extract_pages` пропускает пустой текст, сохраняя исходные номера страниц с 1.
`pages_count` считает все исходные страницы, включая пустые в конце. Чанки
разбиваются по символам без пересечения страниц, с перекрытием и сквозным
`chunk_index`. Требуется `CHUNK_SIZE > 0` и `0 <= CHUNK_OVERLAP < CHUNK_SIZE`.
Документ сначала фиксируется как `processing`, затем атомарно сохраняются чанки
и статус `ready`. При ошибке частичные чанки откатываются, статус `failed`
фиксируется отдельной транзакцией. Пустые/сканированные и зашифрованные PDF
не поддерживаются. Повторная загрузка создаёт отдельную запись, дедупликации нет.

Эмбеддинги: `passage: ` для чанков и `query: ` для запросов,
`normalize_embeddings=True`, 384 измерения. Поиск использует cosine distance
pgvector, `score = 1 - distance`, join с Document и фильтр `status=ready`.
Сходство не является вероятностью правильного ответа. Текст PDF не исполняется
как инструкции. Полный файл не сохраняется; имя используется только как метаданные.
История хранит запрос и источники. Используйте публичные документы в этой
однопользовательской localhost-демонстрации. Ограничение чтения 10 MiB не заменяет
лимит multipart-запроса перед парсингом, изоляцию парсера и защиту от PDF-бомб.
E5 обрезает длинные входы по токенам модели; символьное разбиение не гарантирует
попадание каждого языка в токеновый лимит.

Настройки: `DATABASE_URL`, `EMBEDDING_MODEL`, `EMBEDDING_DIM=384`, `LLM_API_KEY`,
`LLM_MODEL`, `LLM_BASE_URL`, `CHUNK_SIZE=800`, `CHUNK_OVERLAP=100`. Колонка — `Vector(384)`.
При смене модели нужен переиндексированный корпус: версия модели в схеме не хранится.

## Вопросы и история

`answer_question` получает фрагменты через существующий `search_chunks` и отправляет
их как `[1] (filename, стр. N) текст ...`. При отсутствии фрагментов ответ локальный,
без LLM: **В документах нет ответа на этот вопрос.** и `sources=[]`.
При найденных фрагментах и пустом ключе API возвращает 503, а не поддельный ответ.

Используется официальный пакет openai, Chat Completions, `temperature=0`, timeout
30 секунд, без повторов, лимит выхода 2000 токенов, `store=False`, без инструментов.
Базовый URL — `https://api.openai.com/v1`; LLM_BASE_URL позволяет заменить endpoint.
Заменяемая модель по умолчанию — `gpt-5.6-terra`; для неё reasoning отключён, чтобы
поддерживать temperature=0. Другой модели нужна совместимость с этими параметрами.
Сверено с официальными [Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create/)
и [документацией модели](https://developers.openai.com/api/docs/models/gpt-5.6-terra).
Тарифы не измерялись и здесь не заявляются.

Системная инструкция требует язык вопроса, только сведения из фрагментов,
номер [n] после каждого утверждения и точную фразу отказа. Текст и метаданные
документа считаются недоверенными данными. Сервер проверяет диапазон ссылок,
формирует SourceRef только из реально найденных фрагментов и удаляет дубли по
(document_id, page) в порядке первого упоминания. Неверные/отсутствующие ссылки
дают 503. При отказе ответ нормализуется к точной фразе и источники пусты.
Проверка номера источника не доказывает смысловую поддержку утверждения; следование
инструкции о цитате после каждого утверждения и устойчивость к prompt injection
не гарантированы и требуют отдельной проверки с реальной моделью.

Успешные ответы, включая локальный отказ, сохраняются в QueryLog с типом `ask`.
Ошибки провайдера не сохраняются как ответы. История отдаёт вопросы, ответы,
источники и время от новых к старым. В ней могут быть чувствительные данные.

```sh
curl -H 'Content-Type: application/json' -d '{"question":"Где проводится калибровка?","k":5}' http://localhost:8000/ask
curl 'http://localhost:8000/history?limit=20'
```

Живые обращения к LLM не выполнялись. Для отдельной проверки позже потребуются
безопасная настройка ключа и разрешение на платное использование; ключ нельзя
передавать в чат или коммитить. При реальном вызове вопрос и найденные фрагменты
будут переданы выбранному провайдеру. Сейчас ключи не читались и не настраивались.

### Hit@20, RRF и CPU-reranker

Текущий dev-отчёт расширен до шести методов. Hit@20 для базовых методов и
hybrid_rrf — реальное попадание в первые 20. Для e5_rerank/hybrid_rerank это
**покрытие 20 кандидатов до rerank**, а не метрика пяти финальных результатов.
Теперь и базовые методы получают top-20, поэтому условия задержки отличаются
от исходного top-5-прогона выше. Старые отчёты сохранены в истории Git (462a624).

hybrid_rrf объединяет top-20 E5 и top-20 tfidf_char: сумма 1/(60+rank), ранги с 1,
ключ chunk_id, стабильные tie-break по chunk_id. Из объединения до 40 чанков
берутся первые 20 для hybrid_rerank. CrossEncoder — строго
cross-encoder/mmarco-mMiniLMv2-L12-H384-v1, один кешированный экземпляр на CPU,
без trust_remote_code. Входы — сырые пары (query, chunk_text), без префиксов E5.

Задержка rerank включает новый поиск кандидатов и CrossEncoder scoring/ranking;
кандидатные списки не переиспользуются для сокращения измеряемого времени.
Однократные загрузка/прогрев моделей, индексов и пайплайнов вынесены отдельно.
Методы измерены последовательно один раз; задержки могут зависеть от порядка,
состояния прогрева и нагрузки компьютера, а не только состава пайплайна.
